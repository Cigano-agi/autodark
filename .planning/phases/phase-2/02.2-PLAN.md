# Plan 2.2 — Conectar FFmpeg.wasm: WebM → MP4 no Editor

## Goal
O botão "Iniciar Montagem Final" entrega um `.mp4` real (H.264), não um `.webm`. O `useFFmpegExport` já existe e funciona — só precisa ser conectado ao fluxo do Editor.

## Bugs Fixed
- **BUG-104** [critical] — `assembleVideo()` retorna uma blob URL de `.webm` mas o download tem extension `.webm` e o `<video>` pode não tocar em todos os browsers / plataformas de edição (CapCut, DaVinci)
- **BUG-105** [medium] — `useFFmpegExport` nunca é chamado — está implementado mas completamente isolado

## Context

### Fluxo atual (quebrado):
```
assembleVideo() → webmUrl → <video src={webmUrl}> + download "video_final.webm"
```

### Fluxo correto:
```
assembleVideo() → webmBlob → exportToMp4(webmBlob) → mp4Url → <video> + download "video_final.mp4"
```

### Por que WebM primeiro?
`useVideoAssembler` usa `MediaRecorder` — a única API de captura de Canvas disponível no browser.
`MediaRecorder` não grava diretamente em MP4. WebM é o único formato cross-browser.
`useFFmpegExport.exportToMp4()` já faz a conversão WebM→MP4 via FFmpeg.wasm com H.264.

### O que muda no assembleVideo:
`assembleVideo()` atualmente retorna `URL.createObjectURL(blob)` — uma object URL, não o Blob em si.
Para passar para FFmpeg, precisamos do Blob. Temos duas opções:

**Opção A:** Refatorar `assembleVideo` para retornar `{ url: string, blob: Blob }` — mais limpo mas breaking change
**Opção B:** Fazer `fetch(url)` na blob URL para obter o blob — zero impacto no hook, mais simples

Usar **Opção B** — menos risco, zero changes no hook que acabou de ser validado.

```typescript
const handleAssemble = async () => {
  if (allScenes.length === 0) {
    toast.error("Nenhuma cena com imagem disponível para montagem.");
    return;
  }

  try {
    // Etapa 1: Canvas render → WebM
    toast.info("Etapa 1/2: Renderizando cenas...");
    const webmUrl = await assembleVideo(allScenes);

    // Etapa 2: WebM → MP4 via FFmpeg.wasm
    toast.info("Etapa 2/2: Convertendo para MP4...");
    const webmBlob = await fetch(webmUrl).then(r => r.blob());
    URL.revokeObjectURL(webmUrl); // liberar memória do WebM intermediário
    const mp4Url = await exportToMp4(webmBlob);

    setVideoUrl(mp4Url);
    toast.success("MP4 exportado com sucesso!");
  } catch (e: any) {
    toast.error(`Falha na exportação: ${e.message}`);
  }
};
```

## Risks

| Risco | Mitigação |
|-------|-----------|
| FFmpeg.wasm carrega ~30MB na primeira execução | `loadFFmpeg` já tem cache via `ffmpegRef.current?.loaded` — segunda execução é instantânea |
| Vídeo muito longo (15min, 1.5GB WebM) pode exceder memória do browser | Aceitar como limitação conhecida do MVP — documentar no log |
| CORS no fetch da blob URL própria | Blob URLs do mesmo origin não têm CORS — seguro |
