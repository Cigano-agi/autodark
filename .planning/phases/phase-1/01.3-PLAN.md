# Plan 1.3: Corrigir visualAgent + llm.ts — Validação de Scenes e URL Pollinations

## Goal
`extractScenes` lança erro explícito quando a LLM retorna JSON sem `scenes`, e `callPollinationsImage` retorna a URL direta do serviço (não `localhost`) para funcionar em produção.

## Bugs Fixed
- **BUG-009** [critical] — `extractScenes` silencia ausência do campo `scenes`, resultando em capítulo com array vazio e pipeline vazio sem nenhum erro
- **BUG-017** [high] — `callPollinationsImage` retorna `window.location.origin + url` (aponta para `localhost` em dev), quebrando todas as imagens via Pollinations em produção (Vercel)
- **BUG-010** [high] — `generateVisuals` silencia erro de geração de imagem (`catch` sem re-throw), worker não consegue distinguir erro transitório de permanente
- **BUG-018** [medium] — `extractJson` usa regex greedy que captura JSON inválido quando a LLM retorna múltiplos blocos `{}` no mesmo texto

## Context

### BUG-009 — scenes vazio sem erro visível
`visualAgent.ts:47-53`: `extractScenes` faz `parsed.scenes || []`. Quando a LLM retorna JSON em outro idioma (`{"cenas": [...]}`) ou com campo diferente, `parsed.scenes` é `undefined` e o resultado é `[]`. O pipeline continua normalmente mas sem nenhuma cena — o TTS não processa nada, o worker não gera nada, o vídeo final fica vazio. Silêncio total.

### BUG-017 — URL Pollinations aponta para localhost
`llm.ts:108-110`: `callPollinationsImage` constrói `const absUrl = \`${window.location.origin}${url}\`` onde `url` é `/api-pollinations/prompt/...`. Em dev, isso fica `http://localhost:5173/api-pollinations/...` — válido. Em produção (Vercel), o proxy pode não estar configurado ou retornar 404, e mesmo que funcione, a URL armazenada no banco aponta para `localhost` — inválida após a sessão de dev.

A URL direta do serviço é `https://image.pollinations.ai/prompt/...` e é pública sem CORS bloqueado para imagens.

### BUG-010 — generateVisuals engole erro de imagem
`visualAgent.ts:88-93`: bloco catch apenas faz `console.error` e continua. A cena fica com `imageUrl: undefined`. O worker não incrementa `errorCount` nem atualiza status para "error" — não tem como aplicar retry logic com backoff.

### BUG-018 — extractJson regex greedy
`llm.ts:186-213`: `/\{[\s\S]*\}/` captura do primeiro `{` ao **último** `}`. Se a LLM retornar dois JSONs no mesmo texto (ex: reflexão + resultado), o regex monta uma string inválida entre eles. Isso dispara BUG-009 e BUG-011 downstream.

### Task 4: Corrigir extractJson para usar parser balanceado (BUG-018)

**Arquivo:** `src/agents/llm.ts`

**Localização:** linhas 186-213

**BEFORE:**
```typescript
export function extractJson(text: string): Record<string, unknown> {
  // Tenta encontrar JSON dentro do texto
  let match = text.match(/\{[\s\S]*\}/);
```

**AFTER:**
```typescript
export function extractJson(text: string): Record<string, unknown> {
  // Usar parser com balanceamento de chaves em vez de regex greedy.
  // Regex greedy captura do primeiro { ao ÚLTIMO } — quando a LLM retorna
  // dois JSONs no mesmo texto, o conteúdo entre eles gera JSON inválido.
  const firstBrace = text.indexOf('{');
  if (firstBrace === -1) {
    console.error("[extractJson] JSON não encontrado no texto:", text.substring(0, 200));
    throw new Error("JSON não encontrado na resposta");
  }

  let depth = 0;
  let end = -1;
  for (let i = firstBrace; i < text.length; i++) {
    if (text[i] === '{') depth++;
    else if (text[i] === '}') {
      depth--;
      if (depth === 0) { end = i; break; }
    }
  }

  if (end === -1) {
    console.error("[extractJson] JSON não fechado corretamente:", text.substring(0, 200));
    throw new Error("JSON mal-formado: chaves não fechadas");
  }

  const jsonStr = text.slice(firstBrace, end + 1);

  try {
    return JSON.parse(jsonStr);
  } catch (e) {
    // Tenta limpar artefatos de markdown (```) antes de desistir
    const cleaned = jsonStr.replace(/```[\s\S]*$/, "").trim();
    try {
      return JSON.parse(cleaned);
    } catch (e2) {
      console.error("[extractJson] Falha ao parsear JSON:", cleaned.substring(0, 200));
      throw new Error(`JSON inválido: ${(e as Error).message}`);
    }
  }
}
```

## Acceptance Criteria

1. **BUG-009:** Quando a LLM retorna JSON sem campo `scenes`, o pipeline para com mensagem de erro legível (ex: "LLM retornou JSON sem campo 'scenes' para capítulo X. Campos recebidos: cenas") em vez de continuar com 0 cenas.
2. **BUG-017:** Em ambiente de produção (ou abrindo o Network tab do DevTools e inspecionando o valor retornado), a URL de imagem Pollinations começa com `https://image.pollinations.ai/...` — não com `http://localhost:5173`.
3. **BUG-018:** Prompt de teste com dois JSONs no texto (ex: `"Reflexão: {"a":1} Resultado: {"b":2}"`) — `extractJson` retorna `{"a":1}` (o primeiro) sem erro de parsing.
4. `npm run build` passa sem erros TypeScript.
5. `npm run test` retorna verde.

## Risks

| Risco | Mitigação |
|-------|-----------|
| Parser balanceado mais lento em textos longos | Texto de resposta LLM raramente passa de 4KB — performance irrelevante |
| URL direta Pollinations bloqueada por CORS em alguns contextos | O fallback `generateCanvasDarkImage` continua existindo no final da função |
| Re-throw em extractScenes vai crashing o pipeline se LLM sempre retornar campo errado | Correto por design — é melhor um erro explícito do que vídeo vazio silencioso |
