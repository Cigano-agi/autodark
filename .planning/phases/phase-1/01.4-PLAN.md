# Plan 1.4: Corrigir seoAgent + storage.ts — Validação de Output e Upload Seguro

## Goal
`generateSEO` não crasha quando a LLM retorna JSON incompleto, timestamps são calculados a partir da duração real das cenas, e `uploadImage` não persiste URLs de localhost no banco.

## Bugs Fixed
- **BUG-011** [high] — `generateSEO` retorna SEO sem validação, causando `TypeError: seo.tags.join is not a function` no orchestrator linha 382 quando a LLM retorna JSON sem `tags`
- **BUG-012** [medium] — Timestamps do SEO usam `ch.audioDurationSec || 120` mas `VideoChapter` não tem esse campo direto — sempre usa fallback de 120s, gerando timestamps múltiplos de 2 minutos
- **BUG-016** [medium] — `uploadImage` retorna a URL original como fallback quando o fetch falha, persistindo URLs de `localhost` no banco de produção

## Context

### BUG-011 — seoAgent crasha no passo final (85% do pipeline)
`seoAgent.ts:42`: `return extractJson(raw) as unknown as SEOPackage` sem nenhuma validação. Se a LLM retornar JSON com `"tags": null` ou sem o campo, o orchestrator faz `seo.tags.join(", ")` na linha 382 e lança `TypeError`. O pipeline chega a 85%, com visuals e áudio prontos, e crasha sem salvar nada como "awaiting_review". Todo o processamento anterior foi desperdiçado.

### BUG-012 — Timestamps sempre em múltiplos de 2 minutos
`seoAgent.ts:15`: `currentSec += ch.audioDurationSec || 120`. O tipo `VideoChapter` não tem campo `audioDurationSec` — esse campo existe em cada `SceneData`. Então `ch.audioDurationSec` é sempre `undefined` e o fallback de 120s é sempre usado. Resultado: timestamps `0:00, 2:00, 4:00...` independente da duração real.

A duração correta do capítulo é a soma de `scene.audioDurationSec` de todas as cenas.

### BUG-016 — uploadImage retorna URL de localhost como fallback
`storage.ts:55-59`: quando `fetch(imageUrlOrBlob)` falha, o catch retorna `imageUrlOrBlob` (a URL original) como se fosse uma URL persistida. Se a URL original é `https://localhost:5173/api-pollinations/prompt/...` (gerado pelo BUG-017 antes da correção), essa URL inválida é salva no banco de produção. Após corrigir o BUG-017, esse problema diminui — mas o fallback ainda é perigoso para qualquer URL temporária.

## Tasks

### Task 1: Adicionar validação de campos no generateSEO (BUG-011)

**Arquivo:** `src/agents/seoAgent.ts`

**Localização:** linha 42

**BEFORE:**
```typescript
return extractJson(raw) as unknown as SEOPackage;
```

**AFTER:**
```typescript
const seo = extractJson(raw) as SEOPackage;

// Validar e aplicar fallbacks para campos críticos
if (!seo.title || typeof seo.title !== "string") {
  seo.title = title; // fallback para o título do script passado como parâmetro
}
if (!seo.description || typeof seo.description !== "string") {
  seo.description = "";
}
if (!seo.tags || !Array.isArray(seo.tags)) {
  console.warn("[seoAgent] Campo 'tags' ausente ou inválido na resposta LLM — usando array vazio");
  seo.tags = [];
}
if (!seo.chapters || !Array.isArray(seo.chapters)) {
  console.warn("[seoAgent] Campo 'chapters' ausente na resposta LLM — reconstruindo a partir dos capítulos");
  seo.chapters = chapters.map((ch, i) => ({ time: `${i * 2}:00`, label: ch.title }));
}

return seo;
```

> Nota: a assinatura de `generateSEO` já recebe `title` e `chapters` como parâmetros, disponíveis para os fallbacks.

### Task 2: Calcular audioDurationSec real dos capítulos (BUG-012)

**Arquivo:** `src/agents/seoAgent.ts`

**Localização:** linhas 11-16

**BEFORE:**
```typescript
let currentSec = 0;
const chapterTimestamps = chapters.map(ch => {
  const mins = Math.floor(currentSec / 60);
  const secs = currentSec % 60;
  const time = `${mins}:${String(secs).padStart(2, "0")}`;
  currentSec += ch.audioDurationSec || 120;
  return { time, label: ch.title };
});
```

**AFTER:**
```typescript
let currentSec = 0;
const chapterTimestamps = chapters.map(ch => {
  const mins = Math.floor(currentSec / 60);
  const secs = currentSec % 60;
  const time = `${mins}:${String(secs).padStart(2, "0")}`;
  // Somar audioDurationSec de cada cena — VideoChapter não tem audioDurationSec direto
  const chapterDuration = (ch.scenes ?? []).reduce(
    (sum, s) => sum + (s.audioDurationSec ?? 0),
    0
  ) || 120; // fallback de 120s apenas se todas as cenas tiverem audioDurationSec = 0
  currentSec += chapterDuration;
  return { time, label: ch.title };
});
```

### Task 3: uploadImage retorna null em vez de URL inválida (BUG-016)

**Arquivo:** `src/lib/storage.ts`

**Localização:** linhas 54-59

**BEFORE:**
```typescript
try {
  const res = await fetch(imageUrlOrBlob);
  blob = await res.blob();
} catch {
  console.warn("[storage] Failed to fetch image for upload:", imageUrlOrBlob.slice(0, 80));
  return imageUrlOrBlob; // Return original URL as fallback
}
```

**AFTER:**
```typescript
try {
  const res = await fetch(imageUrlOrBlob);
  if (!res.ok) {
    console.warn(`[storage] Fetch de imagem retornou ${res.status} para:`, imageUrlOrBlob.slice(0, 80));
    return null; // Não persistir URL inválida no banco
  }
  blob = await res.blob();
} catch {
  console.warn("[storage] Falha ao buscar imagem para upload:", imageUrlOrBlob.slice(0, 80));
  return null; // Não retornar URL original — pode ser localhost ou URL temporária
}
```

> O caller (`pipelineOrchestrator.ts`) já lida com `null` de `uploadImage` implicitamente via `if (storageUrl) ch.scenes[si] = { ...scene, imageUrl: storageUrl }` — se `null`, mantém a URL que estava antes.

## Acceptance Criteria

1. **BUG-011:** Desconectar da internet após gerar visuals, deixar pipeline chegar ao step SEO — quando a resposta LLM vier truncada, o pipeline não crasha. Deve ou completar com SEO de fallback, ou falhar com mensagem clara em vez de `TypeError`.
2. **BUG-012:** Inspecionar o estado após SEO (DevTools → Network → response do persistStep) — os timestamps no campo `hook` refletem durações próximas das cenas reais (não múltiplos exatos de 120s).
3. **BUG-016:** Verificar no Supabase Storage Console que nenhuma imagem salva tem URL começando com `localhost` após uma sessão de produção.
4. `npm run build` passa sem erros TypeScript — especialmente ao acessar `ch.scenes` que é `SceneData[]` no tipo `VideoChapter`.
5. `npm run test` retorna verde.

## Risks

| Risco | Mitigação |
|-------|-----------|
| `ch.scenes` pode ser `undefined` se `VideoChapter` tiver cenas não inicializadas | Usar `ch.scenes ?? []` no reduce — já incluído no AFTER |
| Fallback de `seo.chapters` reconstroe sem timestamps — pode sobrescrever dados melhores gerados pela LLM | O fallback só é ativado quando `seo.chapters` é nulo/não-array — não substitui dados válidos |
| `uploadImage` retornando `null` pode deixar cenas sem imageUrl em produção | Correto por design — melhor cena sem imagem do que imagem apontando para localhost |

## threat_model

| Threat | Category | Disposição |
|--------|----------|------------|
| URL de imagem de terceiro (Pollinations) salva no banco sem validação de domínio | Spoofing | Accept — imagens são geradas pela própria stack, não por input do usuário |
