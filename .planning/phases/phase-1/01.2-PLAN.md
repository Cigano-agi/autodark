# Plan 1.2: Corrigir narratorAgent — Fallback TTS e Campo failedScenes

## Goal
`generateAllNarrations` retorna `durationSec` estimado corretamente no fallback e expõe `failedScenes` para que o orchestrator possa alertar o usuário.

## Bugs Fixed
- **BUG-007** [critical] — `durationSec: 5.3` hardcoded no catch do TTS corrompendo timestamps do SEO
- **BUG-008** [high] — Ausência de `failedScenes` no retorno impede distinguir "completo com sucesso" de "completo com fallback"

## Context

### BUG-007 — Fallback TTS com duração hardcoded
`narratorAgent.ts:41-49`: quando `callTTS` falha, o catch define `durationSec: 5.3` e `audioDurationSec: 5` independente do texto da cena. O `seoAgent.ts` usa `audioDurationSec` para calcular timestamps dos capítulos. Se 30% das cenas falham, os timestamps ficam comprimidos e errados no YouTube.

A própria `callTTS` em `llm.ts:249` calcula duração com `Math.ceil(text.trim().split(/\s+/).length / 2.5)`. O fallback deve usar o mesmo cálculo.

### BUG-008 — Impossível distinguir sucesso de fallback
O retorno atual é apenas `VideoChapter[]`. O orchestrator não tem como saber quantas cenas falharam no TTS. A barra de progresso mostra 100% mesmo com cenas em `audioUrl: "browser_tts"`.

## Acceptance Criteria

1. **BUG-007:** Cenas com TTS falho têm `durationSec` calculado por `Math.ceil(palavras / 2.5) + 0.3` — não mais `5.3` fixo. Verificável adicionando `console.log(scene.durationSec)` no loop do orchestrator após narração ou inspecionando o estado no DevTools.
2. **BUG-008:** Quando ao menos uma cena falha no TTS, o toast de warning aparece com a contagem. Verificável desconectando da internet, rodando o pipeline e observando o toast.
3. TypeScript compila sem erros: `npm run build` passa.
4. Nenhum teste existente quebra: `npm run test` retorna verde.

## Risks

| Risco | Mitigação |
|-------|-----------|
