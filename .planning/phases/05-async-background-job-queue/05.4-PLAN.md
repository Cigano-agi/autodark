# Plan 5.4: Refatorar `pipelineOrchestrator` — State Machine Reativa

## Goal
`pipelineOrchestrator.ts` chama `saveScene()` para persistir todas as cenas como `pending` antes da geração visual, remove a chamada síncrona a `generateVisuals()` do fluxo principal, e invoca `runVisualWorker()` para processar a fila — com lógica de auto-resume ao remontar o componente quando há cenas `pending`/`processing` em aberto.

## Context
O `runSemiAuto` atual (linha 159 de `pipelineOrchestrator.ts`) executa `generateVisuals()` sincronamente no browser (linha 258-268). Isso significa que fechar a aba durante a geração visual perde todo o progresso. A refatoração move a geração visual para o worker (Plan 5.2), que persiste cada cena individualmente no banco.

**Mudanças exatas a fazer em `pipelineOrchestrator.ts`:**

1. Desestruturar `saveScene` do hook `useProductionState` (atualmente só `saveData` é desestruturado na linha 75)
2. Após `extractScenes()` (step 2.5), salvar cada cena como `SceneSnapshot` com `status: 'pending'` via `saveScene()`
3. Remover o bloco `generateVisuals()` (linhas 257-282) do `runSemiAuto`
4. Chamar `runVisualWorker(channelId)` no lugar de `generateVisuals()`
5. Após o worker terminar, ler as cenas atualizadas do estado do hook (não da memória React — o Realtime já atualizou)
6. Adicionar auto-resume: ao montar o hook, verificar se há cenas `pending`/`processing` e retomar o worker se necessário

**Dados do orchestrator que precisam ser lidos:** As cenas finais com `imageUrl` precisam ser montadas em `chaptersWithVisuals` para passar ao SEO agent e ao assembler. Isso requer ler as cenas atualizadas do `state.scenes` após o worker terminar.

**Dependências:** Plans 5.1, 5.2, e 5.3 concluídos.

```typescript
// Invocar o worker em loop — cada batch processa 5 cenas
// O Realtime (useProductionState) atualiza a UI automaticamente
await logStep(trace, "visual_generation", async () => {
  const totalGenerated = await runVisualWorker(
    channelId,
    (remaining) => {
      const total = allScenes.length;
      const done = total - remaining;
      update({
        progress: 60 + Math.round((done / Math.max(total, 1)) * 20),
        message: `Imagens geradas: ${done}/${total}...`,
      });
    }
  );
  console.log(`[orchestrator] Worker concluiu. Total imagens geradas: ${totalGenerated}`);
}, { provider: "worker-generate-visuals" });

// Reconstruir chaptersWithVisuals a partir das cenas persistidas no banco
// (productionState é atualizado via Realtime — aguardar até que não haja cenas pending)
// Polling com timeout de 10s para garantir que o Realtime atualizou o state
const REALTIME_POLL_INTERVAL = 300; // ms
const REALTIME_MAX_WAIT = 10_000;   // 10s
let waited = 0;
while (waited < REALTIME_MAX_WAIT) {
  const scenes = productionState?.scenes ?? [];
  const stillPending = scenes.filter(s => s.status === "pending" || s.status === "processing").length;
  if (stillPending === 0) break;
  await new Promise(r => setTimeout(r, REALTIME_POLL_INTERVAL));
  waited += REALTIME_POLL_INTERVAL;
}

const persistedScenes = productionState?.scenes ?? [];
const chaptersWithVisuals = chaptersWithAudio.map((ch, ci) => ({
  ...ch,
  scenes: ch.scenes.map((scene, si) => {
    const persisted = persistedScenes.find(
      s => s.chapterIndex === ci && s.sceneIndex === si
    );
    return {
      ...scene,
      imageUrl: persisted?.imageUrl ?? scene.imageUrl,
    };
  }),
}));
```

### Task 3: Adicionar auto-resume ao montar o hook

**Arquivo:** `src/agents/pipelineOrchestrator.ts`

Adicionar um `useEffect` dentro de `usePipelineOrchestrator` para detectar ao montar se há cenas inacabadas e retomar o worker:

Inserir após a linha da declaração de `state` e `reset` (após linha ~81):

```typescript
// Auto-resume: ao montar o componente, verificar se há cenas processing/pending
// Isso acontece quando o usuário fecha e reabre a aba durante a geração visual
useEffect(() => {
  if (!productionState) return;
  if (productionState.status !== "running") return;
  if (productionState.step !== 2.5) return; // Só retomar se estava na etapa de geração visual

  const scenes = productionState.scenes ?? [];
  if (!hasUnfinishedVisuals(scenes)) return;

  console.log("[orchestrator] Auto-resume detectado — retomando worker de geração visual");
  // Iniciar worker em background sem bloquear o render
  runVisualWorker(channelId, (remaining) => {
    update({ message: `Auto-resume: imagens restantes: ${remaining}` });
  }).catch(err => {
    console.error("[orchestrator] Erro no auto-resume do worker:", err);
  });
}, [channelId, productionState?.status, productionState?.step]);
// Dependências intencionalmente limitadas: apenas status e step para não re-disparar em cada atualização de cena
```

## Risks

| Risco | Probabilidade | Mitigação |
|-------|---------------|-----------|
| `productionState` é `null` ao reconstruir `chaptersWithVisuals` | Média | Guard `productionState?.scenes ?? []` — se vazio, `chaptersWithVisuals` usa os dados em memória de `chaptersWithAudio` sem `imageUrl` (Plan 5.5 tolera imagens faltando) |
| Race condition: `saveScene` em loop concorrente com audio loop | Baixa | `saveScene` é chamado apenas uma vez após `extractScenes`, não durante audio — sem concorrência |
| `allScenes` referenciado no bloco de `runVisualWorker` mas declarado antes na closure | Baixa | TypeScript/closure — `allScenes` é declarado no mesmo escopo do `runSemiAuto`, acessível pelo callback |
| `useEffect` de auto-resume dispara múltiplas vezes | Baixa | Dependências limitadas a `status` e `step` — muda no máximo uma vez por sessão de geração |
| Import de `useEffect` já existia — duplicar no import | Nenhum | TypeScript/editor detecta duplicação; garantir lista de imports sem duplicatas |
