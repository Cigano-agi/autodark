# Plan 5.5: Ajustar `useVideoAssembler` — Placeholder em img.onerror e Guard de Cenas Essenciais

## Goal
`useVideoAssembler.tsx` não aborta a montagem quando uma imagem falha ao carregar — usa canvas preto como placeholder silencioso. O chamador (`pipelineOrchestrator`) verifica que pelo menos 80% das cenas têm `imageUrl` antes de chamar `assembleVideo`, prevenindo montagem com fila incompleta.

## Context
A linha crítica atual em `useVideoAssembler.tsx` (linha 162):
```typescript
img.onerror = () => reject(new Error(`Falha ao carregar imagem da cena ${i + 1}`));
```
Isso faz `Promise.reject` quando qualquer imagem falha, abortando **toda** a montagem. Com o novo modelo assíncrono, imagens vêm do Supabase Storage — qualquer falha transiente de rede, CORS temporário, ou cena que ficou em `status: "error"` (3 tentativas falhas) cancela a montagem completa.

A solução tem duas partes:
1. **`useVideoAssembler.tsx`:** Substituir `reject` por canvas preto como frame de placeholder — montagem continua
2. **`pipelineOrchestrator.ts`:** Verificar completude da fila antes de chamar `assembleVideo` — não iniciar com fila parcialmente processada

**Por que canvas preto e não URL de placeholder:** O assembler usa `HTMLImageElement` para `drawImage` no Canvas. Usar uma imagem de placeholder externa adicionaria uma dependência de rede. Canvas preto é gerado localmente, sem latência, sem falha de rede.

**Dependências:** Plan 5.4 concluído (orchestrator integrado com worker).

### Task 1: Substituir `img.onerror = reject` por placeholder canvas em `useVideoAssembler.tsx`

**Arquivo:** `src/hooks/useVideoAssembler.tsx`

**Mudança 1 — Adicionar função `createPlaceholderImage` antes do hook (após linha 130):**

```typescript
/**
 * Cria um HTMLImageElement com canvas preto cinematográfico como placeholder.
 * Usado quando uma imagem de cena falha ao carregar — evita abortar a montagem.
 */
function createPlaceholderImage(width: number, height: number, sceneLabel: string): HTMLImageElement {
  const canvas = document.createElement("canvas");
  canvas.width = width;
  canvas.height = height;
  const ctx = canvas.getContext("2d")!;

  // Fundo preto
  ctx.fillStyle = "#000000";
  ctx.fillRect(0, 0, width, height);

  // Gradiente sutil para dar profundidade cinematográfica
  const grad = ctx.createRadialGradient(width / 2, height / 2, 0, width / 2, height / 2, height * 0.6);
  grad.addColorStop(0, "rgba(30, 30, 30, 0.3)");
  grad.addColorStop(1, "rgba(0, 0, 0, 0)");
  ctx.fillStyle = grad;
  ctx.fillRect(0, 0, width, height);

  // Label da cena (debug visual)
  ctx.fillStyle = "rgba(255, 255, 255, 0.15)";
  ctx.font = "bold 24px Arial, sans-serif";
  ctx.textAlign = "center";
  ctx.textBaseline = "middle";
  ctx.fillText(sceneLabel, width / 2, height / 2);

  const img = new Image();
  img.src = canvas.toDataURL("image/jpeg", 0.8);
  return img;
}
```

**Passo A — Adicionar `loadImageWithFallback` junto com `createPlaceholderImage`:**

```typescript
// Adicionar função auxiliar antes do hook, junto com createPlaceholderImage:
async function loadImageWithFallback(
  src: string,
  width: number,
  height: number,
  sceneLabel: string
): Promise<HTMLImageElement> {
  return new Promise<HTMLImageElement>((resolve) => {
    const img = new Image();
    img.crossOrigin = "anonymous";
    img.onload = () => resolve(img);
    img.onerror = () => {
      console.warn(`[assembler] Falha ao carregar ${src.slice(0, 60)}... — usando placeholder`);
      resolve(createPlaceholderImage(width, height, sceneLabel));
    };
    img.src = src;
  });
}
```

E o bloco de carregamento fica:
```typescript
// ── Load all images (com placeholder silencioso em caso de falha) ────────────
setLog("[autodark] Carregando imagens...");
const images: HTMLImageElement[] = [];
let imagesWithPlaceholder = 0;

for (let i = 0; i < scenes.length; i++) {
  setLog((p) => p + `\n[autodark] Carregando cena ${i + 1}/${scenes.length}...`);
  const scene = scenes[i];

  if (!scene.imageUrl) {
    images.push(createPlaceholderImage(WIDTH, HEIGHT, `Cena ${i + 1}`));
    imagesWithPlaceholder++;
    continue;
  }

  const img = await loadImageWithFallback(scene.imageUrl, WIDTH, HEIGHT, `Cena ${i + 1}`);
  // Verificar se veio do placeholder (naturalWidth === WIDTH indica canvas)
  if (img.naturalWidth === WIDTH && img.naturalHeight === HEIGHT && !scene.imageUrl.startsWith("data:")) {
    imagesWithPlaceholder++;
  }
  images.push(img);
}

if (imagesWithPlaceholder > 0) {
  setLog((p) => p + `\n[autodark] ${imagesWithPlaceholder} cena(s) com placeholder`);
}
```

// Guard: verificar que pelo menos 80% das cenas têm imagem antes de montar
// (cenas com status 'error' após 3 tentativas ficam sem imageUrl — tolerado)
const persistedScenes = productionState?.scenes ?? [];
const scenesWithImage = persistedScenes.filter(s => s.imageUrl && s.imageUrl !== "");
const completionRatio = persistedScenes.length > 0
  ? scenesWithImage.length / persistedScenes.length
  : 1;

if (completionRatio < 0.8) {
  console.warn(
    `[orchestrator] Apenas ${scenesWithImage.length}/${persistedScenes.length} cenas com imagem ` +
    `(${Math.round(completionRatio * 100)}%) — abaixo do threshold de 80%.`
  );
  toast.warning(
    `${scenesWithImage.length}/${persistedScenes.length} imagens geradas. ` +
    "Montando com placeholders para as cenas faltando."
  );
  // Não lançar erro — continuar montagem. useVideoAssembler usa placeholder silencioso.
  // Apenas registrar para rastreabilidade.
}

// Reconstruir chaptersWithVisuals com imageUrls do banco
const chaptersWithVisuals = chaptersWithAudio.map((ch, ci) => ({

## Risks

| Risco | Probabilidade | Mitigação |
|-------|---------------|-----------|
| `createPlaceholderImage` usa `canvas.toDataURL` que pode falhar em ambientes sem GPU | Muito baixa | Browser-only — canvas sempre disponível em Chrome/Firefox/Safari modernos |
| `loadImageWithFallback` resolve com placeholder mas `images[]` fica com comprimento errado | Baixa | Loop `for` com `push` direto mantém correspondência por índice; verificar `images.length === scenes.length` após o loop |
| 20% de cenas com placeholder gera vídeo visualmente degradado | Aceitar | Documentado no toast ao usuário; alternativa é abortar, o que é pior (perde todo o trabalho) |
| `img.crossOrigin = "anonymous"` causa CORS preflight que falha para URLs da AI33 (CDN sem CORS headers) | Média | `loadImageWithFallback` já usa `crossOrigin` na primeira tentativa; se falhar, resolve com placeholder — o vídeo monta sem CORS error |

## threat_model

### STRIDE Threats

| ID | Categoria | Componente | Disposição | Mitigação |
|----|-----------|------------|------------|-----------|
| T-5.5-01 | Tampering | URL de imagem vinda do banco pode apontar para domínio externo malicioso | Aceitar | `<img>` com `crossOrigin="anonymous"` previne leitura de pixels de outros domínios via Canvas (CORS); não há execução de código — apenas renderização visual |
| T-5.5-02 | Denial of Service | Loop de carregamento de imagens pode travar se uma URL nunca resolve nem rejeita | Mitigar | `loadImageWithFallback` depende de `img.onerror` que é disparado pelo browser em timeout de rede; browsers modernos têm timeout implícito para requests pendentes (~60-90s) |
| T-5.5-03 | Information Disclosure | URLs de imagens do Storage aparecem no `log` do assembler | Aceitar | Log é visível apenas ao usuário logado na mesma sessão; URLs de Storage têm acesso público intencional (bucket `images` é público) |
